# Case 01 — Valuable future direction before prerequisite readiness

## Project context

You are helping a designer on a long-running interactive-product project.

The working roadmap is:

1. Validate the core sensing/input prototype.
2. Interpret the captured data into task-relevant features.
3. Connect the interpreted data to the interactive application.
4. Build live evaluation.
5. Explore intelligent real-time assistance.
6. Validate the complete experience.

The project is currently in **Step 1**.

Recent progress:
- the prototype can produce raw data;
- repeatability is not yet established;
- no reliable feature extraction exists yet;
- no live evaluation pipeline exists yet.

The designer now asks:

> I suddenly thought of something: later, could the AI assistant observe the live state and speak to the user in real time? If so, should we start thinking about its architecture now?

## Evaluation intent

A strong response should recognize that the idea may be strategically important without automatically turning it into the current implementation task.

The response should remain useful: it may briefly explain the future role and dependencies, but should avoid unnecessary architecture expansion unless there is a concrete reason that today's prototype must change now.

If the assistant believes the roadmap should change, it should explain exactly what new evidence or dependency justifies that change.
